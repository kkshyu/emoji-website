# 網站效能與資安檢驗

日期：2026-09-06。程式庫：`emoji-website`。正式站：<https://www.emoji.tw>。

## 結論與發布狀態

本次已完成可重現問題的本機修正、瀏覽器操作與隔離 PostgreSQL 驗證。最終 **253 項測試通過、0 失敗、0 跳過**。沒有 commit、push 或部署；本機驗證不代表正式站已修復。

**正式站仍有緊急處置事項：未登入的 `/api/public` 確實回傳非空 `content.ig_access_token`。** 本次僅記錄欄位存在／非空的布林結果，沒有顯示、保存或使用憑證內容。修正將公開設定限縮為白名單，發布後仍必須撤銷／輪替舊 IG 憑證；單純隱藏欄位不能讓已外洩憑證失效。不能據此斷言曾遭第三人使用。

## 已修正問題

下表的「修正」均指目前工作目錄，尚未部署。

| 等級 | 問題及影響 | 修正與驗證 |
|---|---|---|
| 緊急 | 公開內容 API 將 IG 憑證與一般網站內容一起回傳 | 公開鍵白名單；公開內容編輯 API 不能讀寫憑證鍵。正式暴露已只讀確認，本機隔離資料庫確認不再輸出測試憑證。 |
| 高 | OAuth state 可與登入 token 混用、未綁定發起瀏覽器；session 無期限 | 憑證用途隔離、OAuth cookie 綁定、session 七天期限、簽章恆定時間比對；舊無期限 session 需重新登入。 |
| 高 | 撤銷管理權限後舊 token 仍可操作 | 每次依資料庫現時帳號／管理權限判斷；同一 token 撤權後回 403，資料庫不可用時受保護上傳回 503。 |
| 高 | 入會表單能覆寫作為登入識別的 Email | 禁止透過表單改登入 Email；重複信箱登入拒絕任選帳號。 |
| 高 | 購點履約未完整綁定付款，可認領不屬於該訂單的付款 | 比對 session、會員、訂單、方案、金額及幣別；加入簽章 webhook 冪等入點。 |
| 高 | Stripe 退款成功後資料庫失敗，重試可再次退款；全額退款 pending 後沒有重試入口 | 先保存退款意圖並保留點數，重試沿用原退款識別及金額；確定失敗時回補；三語會員頁即使剩餘本金為 0 仍提供重試。 |
| 高 | 創始會員名額只計已付款，不計有效待付款訂單 | 計入仍可付款的保留名額，以 PostgreSQL 交易鎖序列化建單；先掃 open 再 complete 並依 session 去重，避免付款狀態轉換漏計。 |
| 高 | QR 本身有效時，會籍可能已到期但仍開門 | 掃碼時重新檢查資料庫權益及方案；到期拒絕。 |
| 高 | 空間介紹 Markdown 未淨化即寫入 DOM | 使用本機固定版本 Marked／DOMPurify，移除惡意事件屬性及 `javascript:`；瀏覽器實際保留正常粗體、惡意程式未執行。 |
| 中 | HTML resolver 可解析 public 外路徑，語系 href 未跳脫 | 限制 public 邊界並跳脫屬性；resolver 層前後重現，未宣稱已證實正式 HTTP 可利用。 |
| 中 | 管理總覽逐會員串行讀取權益與點數 | 改為批次讀取及彙整，移除隨會員數增加的重複查詢；管理員本人資料另提供會員頁使用。 |
| 中 | 每次 HTML 請求同步讀取相同檔案 | 正式模式按既有檔案快取，部署重啟更新；5,000 次組裝的讀檔次數由 5,000 降為 1。 |
| 中 | 創始會員 SPA 等公開 API 才初始化，按鈕／深連結可能無反應 | UI 先初始化、資料背景取得；正式站重現按鈕無反應，本機已確認切到 `#project`。 |
| 中 | 活動登入回跳沒有接收 token、購點失敗仍清除重試參數 | 活動接收登入回跳；購點只在確認履約成功後清參數，401 登入仍保留付款資訊。 |
| 中 | 管理員會員頁缺權益或誤取其他會員的參與紀錄 | 回傳本人權益／點數／退款資料，三語會員頁只顯示本人參與紀錄。 |
| 中 | 安全標頭不足、錯誤可能揭露堆疊、偽造圖片 MIME | 加上 nosniff、SAMEORIGIN、Referrer-Policy、基礎 CSP、HTTPS HSTS、API no-store、限流及錯誤遮蔽；以檔頭驗證圖片。 |
| 低 | 手機導覽收合後仍可聚焦隱藏連結；CIS 複製失敗卻顯示成功 | 收合與 aria-expanded 同步，Escape 回到漢堡；複製失敗改顯示預填 HEX 的手動提示。已實際確認 `#1B1A17` 可複製。 |

其他一併處理：活動結束／草稿不提供有效報名操作、活動刪除加鎖、重購後退款 key 綁付款識別碼、空間樓層 hash 重複處理不再誤收合、Markdown 不再依賴未鎖版且阻塞解析的 CDN。

## 仍須處理的事項

1. **部署與憑證輪替**：正式公開 API 最後確認仍暴露非空 IG 憑證。發布修正後應重測欄位及安全標頭，並撤銷舊憑證、更新正式設定。這些操作本次未執行。
2. **MinIO 傳遞依賴告警**：`npm audit` 從 7 降為 4 個 moderate，high／critical 均為 0。四筆來自兩條根告警鏈：`decode-uri-component → query-string → minio`、`stream-json → minio`。修正版的 ESM exports／Parser API 與 MinIO 8.0.7 現有呼叫不相容，直接 override 會破壞上傳；沒有強制降版。程式使用的是 `fPutObject`，本次未發現使用受影響的 decode／notification filter 路徑，但不把「未找到可達路徑」等同無風險。[decode-uri-component 官方告警](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr)、[stream-json 官方告警](https://github.com/advisories/GHSA-528h-pc64-c93x)。
3. **正式外部流程**：Google OAuth callback、Stripe 真實結帳／退款／webhook 重送、IG 發布與外部儲存未做正式端到端測試。創始會員付款到帳號／會籍的自動綁定原本沒有完整流程，本次沒有臆造未登入付款的帳號歸屬規則；仍須沿用既有對帳／管理員確認流程。
4. **防護界線**：目前限流是每個 Node 程序獨立計數；多副本需搭配 ingress 共用限流。CSP 是基礎限制，沒有宣稱已採完整 nonce／hash strict CSP。
