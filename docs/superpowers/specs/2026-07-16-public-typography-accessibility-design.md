# 官網字級可讀性設計規格

## 目標

讓正式官網所有傳遞資訊的可見文字，在預設 100% 縮放與所有響應式斷點下，實際字級皆不低於 `1rem`（通常為 16 CSS px），並維持 WCAG 2.2 AA 所要求的放大、重排與文字間距適應能力。

`16px` 是本站採用的 UX 內控，不宣稱為 WCAG 明訂的最小字級。WCAG 2.2 真正相關的要求是 1.4.3 對比、1.4.4 文字可放大 200%、1.4.10 在 320 CSS px 下重排，以及 1.4.12 使用者覆寫文字間距後不遺失內容或功能。

## 範圍

納入正式公開頁面：

- 三語首頁、關於、交通、空間、消費制度。
- 三語創始會員、社群夥伴、新創輔導、CIS。
- 三語會員專區的訪客畫面，以及原始碼中登入後才出現的會員文字與表單控制項。
- 共用導覽、語言選單、按鈕、頁尾、提示、toast、modal 與動態插入內容。

不納入：

- `/admin` 與 `access-mock.html` 等內部工具頁。
- IG Studio 的 1080px 海報本體與縮圖預覽；海報輸出尺寸不等同瀏覽器閱讀字級。
- 已以 `aria-hidden="true"` 標記的創始席位裝飾字、純裝飾偽元素與 SVG logo。

## 現況證據

正式站以 Chromium 實測 30 個路由、320px 與 1440px 兩種 viewport，共 60 次渲染：每個路由都有低於 16px 的文字，最小約 9.25px。共用導覽品牌副標為 9.6px；首頁數字單位手機約 9.25px；創始會員副標約 9.84px。問題來自共用設計尺度，而非單一頁面。

## 設計決策

1. 所有有意義文字的 `font-size` 下限為 `1rem`。
2. 原本使用固定小字的規則直接提高到 `1rem`；不新增字級元件、設計 token 或第三方套件。
3. 需要跟隨大型父文字縮放的單位或副標，改用 `max(1rem, <既有相對值>)`，保留大尺寸比例並防止手機斷點縮得過小。
4. 視覺層級改由字重、顏色、字距與留白維持，不再以 10–13px 小字建立層級。
5. 表單控制項、按鈕與輸入值直接指定或繼承至少 `1rem`，避免行動瀏覽器聚焦時因小於 16px 自動放大。
6. 文字變大後允許自然換行與區塊增高；不得以裁切、縮放或省略文字來維持原高度。

## 修改方式

先修三個共用來源：

- `public/nav.css`：全站導覽與頁尾。
- `public/style.css`：首頁及一般內容頁的共用尺度。
- `public/fellow/styles.css`、`public/fellow/founding.css`：三個計畫頁與會員相關元件。

再機械式修正專頁 CSS 與三語重複的 inline／動態樣式；不趁機搬檔、抽象化或重構三語模板。

## 回歸檢查

新增一個無依賴的 Node 測試 `scripts/test-public-typography.mjs`，由既有 `npm test` 自動執行：

- 掃描正式公開頁面使用的 CSS、HTML 與自有 JavaScript。
- 阻擋低於 `1rem`、`16px`、`12pt` 或 `100%` 的字級宣告，以及沒有下限的縮小相對值。
- 失敗時輸出檔名、行號與違規值。
- allowlist 只列本規格明確排除的裝飾文字；內部工具與 vendor 檔直接排除掃描。

驗收時再以現有 Playwright 對正式路由做 computed-style 實測：

- 30 路由 × 320px／1440px，所有有意義文字不得低於 16px。
- 200% 文字放大後不得裁切、重疊或遺失功能。
- 320 CSS px 下不得因一般文字產生雙向捲動；地圖等必要二維內容另行判讀。
- 套用 WCAG 1.4.12 的行高、段後、字距與詞距覆寫後不得裁切或重疊。
- 重跑完整 `npm test`。

## 完成條件

- 公開路由的有意義文字實測最小值為 16px。
- 靜態字級防退步測試與既有完整測試通過。
- 手機、桌機、200% 放大與文字間距覆寫均無新增的內容裁切、重疊或非必要橫向捲動。
- 不新增執行期依賴，不改後端、資料庫、文案或資訊架構。
