# 會員頁 UX／版面優化設計

日期：2026-07-12  
狀態：已核准（示意 v8）  
範圍：`public/member.html`（及 `en/`、`ja/` 對應頁，i18n 文案同步）  
相關：`2026-07-12-member-active-access-design.md`、`2026-07-12-member-points-design.md`  
示意參考：brainstorm session 內 `member-page-full-v8.html`（本機 `.superpowers/brainstorm/`，已 gitignore）

## 目標

全面優化會員頁體驗與資訊架構：

1. **主職清楚**：頁面主要呈現「目前狀態」（會籍），不是功能堆疊。
2. **現場進出濃縮**：Active 狀態與 QR 收在右上角；點擊後全螢幕出示。
3. **同頁降權**：點數、活動列表、動態、創始引導仍在同頁，視覺權重低於狀態／通知／錢包主卡。
4. **語氣**：狀態區採活潑 HUD（進度、微黃光暈）；點數區資訊極簡但卡片語彙與 HUD 一致。
5. **補齊旅程**：購／續會籍、個人資料、操作 toast、非 Active 引導（取代裸 `alert` 與空洞狀態）。

## 非目標

- 成就／印章／等級／排行榜。
- 另開 `/member/*` 子路由（展開、modal、overlay 即可）。
- 改動 active／entitlements／QR／點數後端規則（僅改呈現與前端互動）。
- 改創始認購金額或條款本文。

## 方法

**A′ — 單頁、狀態主體、右上進出控件（已選）**

否決：任務分頁（現場多一步）；雙欄儀表板（手機／單手弱）；常駐大 QR（佔用主體）。

## 頁面結構（上→下）

```
[站點 nav]
歡迎＋編輯資料                    [Active·QR 右上角控件]
[下一場活動通知卡]                 ← 無下一場則整張隱藏
[目前狀態 HUD 卡]
[點數錢包卡]
近期活動（降權列表）
會員動態（降權）
創始計畫引導（降權一行）
登出
```

Admin 若需進後台：維持既有入口，視覺不壓過狀態卡（次要連結或動作列即可）。

## 右上角 Active／QR

| 狀態 | 呈現 | 互動 |
|------|------|------|
| Active | 黃點＋「Active」＋QR icon | 點擊 → 全螢幕／深色 overlay 大 QR；既有 30 秒刷新；可視時刷新 |
| 待啟用 | 「待啟用」＋QR icon | 可點；出示首次啟用 QR |
| 非 Active／無可發碼 | 灰態「未啟用」 | 不可發無效 QR；點擊給簡短說明並引導至購買會籍 |

Overlay：大 QR、方案／效期摘要、關閉（× 或點背景）。Token 備用字串可收在「進階」或不預設露出，避免干擾掃碼。

## 下一場活動通知卡

- 置於「目前狀態」**上方**。
- 內容：眉標「下一場活動」、標題、時間／地點／報名狀態、次要 CTA（查看 → 捲至活動列表或展開該場）。
- **下一場定義（唯一）：** 在 `events` 中，取「已報名且 `starts_at` 最早的未來場」；若無，則取「未開始且 `starts_at` 最早的一場」。兩者皆無 → **整張不渲染**。
- 視覺：輕黃底提示卡，與右上 Active 黃點並存時注意 CIS「黃當底」；通知卡可用淡黃底，主 ink CTA。

## 目前狀態卡（HUD）

**標題列**

- 左：`目前狀態`（小 caps／letter-spacing）
- 緊接其後弱化：`· No. {會員編號}`。編號優先 `commitment.cert_no`（創始）；否則不顯示編號段（不拿內部 user id 充當對外編號）。

**主標**

- 依狀態變文案，例如：月票進行中／待首次進場啟用／會籍已到期／尚未有會籍…

**會期進度**

- 有明確起迄才顯示進度條＋「還有 N 天」。
- **同一列弱化**右側：方案名＋會籍期間（較小、muted）；不另做粗字鍵值列搶戲。
- 待啟用：進度改說明「首次進場後起算」；期間可顯示待定或購買日提示。

**按鈕（同一排、兩欄等寬）**

- 主：續訂／升級（或無會籍時「購買會籍」）
- 次：方案說明（展開方案或連到說明）
- 同排 `grid 1fr 1fr`，不要直向堆疊。

**不放**：點數餘額（改由點數錢包負責）。

## 點數錢包卡

與狀態卡**同款卡片語彙**（描邊、圓角、雙格、陰影層級接近），避免過空或過重的「理財報表」。

**預設只顯示**

1. **可用**點數（大數字）
2. **快過期**點數＋最近到期日（無快過期則隱藏該格或整側，勿硬塞 0 誤導）

**拿掉預設露出**：點數組成條、購買點／加贈分項、長規則說明、訂單列表。

**標題列**：左「點數錢包」；右次級「紀錄與退款」（展開訂單／退款）。

**按鈕（同一排、兩欄）**：購買點數｜兌換服務。

**用詞（白話，禁止投資術語）**

| 不用 | 使用 |
|------|------|
| 申購／持倉／本金／贖回 | 購買點數／點數組成（僅展開時）／購買點／退款 |
| 點數帳戶／POINTS ACCOUNT 作主標 | 點數錢包 |

兌換仍須 Active（既有規則）；非 Active 時兌換區說明需可進出二三樓。

成功／失敗以 **toast** 回饋，取代 `alert`／`prompt` 為主路徑（退款金額輸入可用輕量 modal）。

## 同頁降權區

- **近期活動**：完整列表與報名／取消（通知卡只是捷徑）。
- **會員動態**：既有 updates feed。
- **創始**：非創始一行引導；創始者可顯示徽章／憑證於降權區或狀態卡副標（不壓過主標）。
- 字級、對比、陰影皆弱於上方三卡。

## 補齊旅程（前端）

| 旅程 | 行為 |
|------|------|
| 購／續會籍 | 狀態卡 CTA → 展開方案。創始走既有 Fellow／認購連結；單日／月／季／年若尚無會員自助結帳 API，本輪做 UI 展開＋導向既有購買入口（或明確「即將開放」），不在本 spec 新造付款後端。 |
| 個人資料 | 「編輯資料」→ 輕量面板；顯示名可編（若無 PATCH API 則本輪只做 UI＋唯讀回退）；email 唯讀；頭像不做。 |
| 回饋 | toast：報名、兌換、購點導轉前、退款結果、錯誤可重試 |
| 非 Active | 右上不假裝可掃；狀態主 CTA 購買／啟用 |

## i18n

`zh`／`en`／`ja` 三語鍵同步；用語保持各語言日常口吻，不引入金融黑話。

## CIS／視覺約束

- 沿用 `style.css` token：墨／紙／唯一黃 `#FFDE34`。
- 黃作底色或 Active 指示，不作大面積文字色。
- 動作回饋可有短 pulse／toast 滑入；尊重 `prefers-reduced-motion`。

## 實作備註

- 主要改 `public/member.html` 的結構、CSS、`renderMember`／`renderAccess`／`renderPoints` 與相關 I18N；必要時抽小組件函式保持可讀。
- QR 刷新邏輯沿用；改為 overlay 開啟時啟動、關閉時可暫停（省請求）。
- 「快過期」定義：`expires_at` 非 null、且落在此刻起 **30 天內**（前端常數 `EXPIRING_WITHIN_DAYS = 30`）的 lots，加總 `remaining`；最近到期日取其中最早的 `expires_at`。無符合 lot → 不渲染快過期格。
- 會員編號：僅 `cert_no`；無則標題列只留「目前狀態」。

## 驗收

1. 首屏一眼看到歡迎、右上進出、通知（若有）、狀態卡；QR 不常駐大圖。
2. 點右上可出示／關閉 QR；非 Active 不發無效碼。
3. 狀態卡無點數格；有期間弱化於進度列；雙鈕同排；編號在「目前狀態」後。
4. 錢包預設只有可用＋快過期；雙鈕同排；無申購／本金等用語。
5. 活動／動態／創始同頁且明顯較弱。
6. 報名／兌換等以 toast 回饋；三語不破版。
