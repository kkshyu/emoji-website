# MinIO 依賴修復

日期：2026-09-06。本次範圍是網站圖片上傳用戶端套件；MinIO 儲存服務、既有物件、正式設定與 IG 排程均未變更。

## 修正

移除 `minio@8.0.7` 及其受告警影響的傳遞依賴，將 `lib/ig-publisher.js` 唯一的 `fPutObject` 呼叫改為官方 `@aws-sdk/client-s3@3.1127.0` 的 `PutObjectCommand`。

- 保留 `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_PUBLIC_BASE` 介面，以及原本的 bucket／物件鍵／公開網址。
- 採 path-style，region 預設為 MinIO 常用的 `us-east-1`；非預設區域可用 `S3_REGION` 指定。舊 SDK 會自動查區域，新實作改為明確設定。
- 直接上傳 Puppeteer 回傳的 JPEG 位元組，不再為 S3 上傳留下暫存圖片；未配置 S3 時，原本本機 uploads 行為保留。
- 關閉用戶端連線並確保瀏覽器在成功／失敗後關閉；上傳失敗會中止後續頁面。
- Node 最低版本改為 `22.12.0`，符合既有 Puppeteer 的實際要求；正式 Docker 採 Node 22。

採用 `requestChecksumCalculation: WHEN_REQUIRED` 避免非必要 checksum／trailer 造成舊 S3 相容服務差異；回歸測試確認 HTTP 請求保持原始 JPEG，並包含 SigV4 簽章及正確 SHA-256。[AWS checksum 設定說明](https://docs.aws.amazon.com/sdkref/latest/guide/feature-dataintegrity.html)
